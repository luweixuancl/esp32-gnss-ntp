# 正式产品状态显示调研与本项目方案

> 状态：**P0–P2 已落地并随后续版本保留** · 当前 UI 基线见 [CURRENT.md](CURRENT.md)（**v1.1.39**）  
> 初版落地：v1.1.17–v1.1.19（2026-09-18）
> 范围：网页状态页 / OLED / 状态灯 / 观测接口的信息架构与刷新策略  
> 相关：[status_json_1hz_cadence_20260918.md](status_json_1hz_cadence_20260918.md)、[ext_clock_design.md](ext_clock_design.md)、[s3_deep_dive_roadmap.md](s3_deep_dive_roadmap.md)

## 1. 调研对象与共性

| 产品档 | 代表 | 主显示面 | 状态语义 |
|--------|------|----------|----------|
| 企业机架 NTP | **Meinberg** LANTIME / meinbergOS | Web Dashboard 磁贴 + 面板 LCD | 绿=锁定 · 黄=同步中/Holdover · 红=故障/自由跑 |
| 专业桌面 GNSS NTP | **LeoNTP** | OLED 多屏（时间主屏优先）+ 可选公网统计页 | PPS 圆点绿/棕/红；时间色提示未驯服；负荷条 |
| 入门商用 | **TimeMachines TM1000A** | 三灯（电源/锁定/秒闪）+ 配置页静态状态 | 灯看健康；网页时间常是「刷新瞬间快照」 |

### 1.1 正式产品几乎一致的原则

1. **一眼健康色**：同步态用绿/黄/红（或等价图标），不靠用户读 `residualMs`。
2. **时间是英雄信号，但不是唯一真相源**：面板/OLED 大字走本地驯服钟；网页时间多为「校准点 + 本地外推」或刷新快照——**几乎没有产品用 HTTP 轮询当秒脉冲**。
3. **分层信息**：
   - L0 健康（能否授时 / 参考是否锁）
   - L1 时间与网络身份（UTC/本地、IP、SSID）
   - L2 参考质量（星数、PPS、频偏、色散）
   - L3 服务计数与策略（served、RATE、ACL）——默认折叠或次屏
4. **面板与网页分工**：面板/OLED = 机房扫一眼；网页 = 配置 + 细项；长测/图表走外部监控（Prometheus / Influx），不塞进状态首页。
5. **刷新策略务实**：Meinberg 仪表盘轮询状态 API；TM1000A 网页时间随刷新静态；LeoNTP 公网统计页也是聚合计数——**秒级 UI 平滑靠本地钟，不靠推送全量 JSON**。

### 1.2 对本项目的启示

- 本机已有：OLED 大字时间 + 灯语 + `/` 四卡片 KV 列表 + `/status` + `/metrics`。
- 短板不在「字段不够」，而在 **网页把工程师调试表当成了产品首页**，且曾把「秒是否跳动」绑在 `/status` RTT 上（已用外推缓解）。
- 不需要 Meinberg 级 Dashboard 引擎；应对齐 **LeoNTP 主屏哲学 + Meinberg 三色语义 + TM 灯语简洁**。

## 2. 本项目现状（对照）

| 面 | 现状 | 与正式产品差距 |
|----|------|----------------|
| OLED Home | 大字本地时、星数·LCK、RSSI、SSID、IP、SYNC/WAIT、FW 标记 | 已接近 LeoNTP 主屏；可加强「能否授时」色/标记 |
| 状态灯 | 网络 / 时钟 / 授时（S3 含 B） | 已具备 L0；文档化即可 |
| Web `/` | 约 30 行 KV：NTP/GPS/计数/系统平铺 | 缺「首屏英雄态」；工程字段过多抢视线 |
| `/status` | 全量 JSON，~1 Hz 拉取 | 适合调试；不适合当 UI 时钟源 |
| `/metrics` | Prometheus | 已对齐正式可观测路径 |

## 3. 目标信息架构（推荐）

### 3.1 三色授时态（全表面统一）

| 色 | 条件（与现 NTP 诚实语义对齐） | 文案建议 |
|----|-------------------------------|----------|
| **绿** | `stratum1Ready`（LCK + PPS + 授时中） | Stratum 1 |
| **黄** | 仍授时但降级：DEG / HLD / OTA 外的弱同步 | 守时 / 降级 |
| **红** | 不授时：UNS / ACQ 未就绪 / OTA refuse | 未同步 |

OLED 的 SYNC/WAIT、网页主徽章、灯语 B 通道语义应共用这一张表。

### 3.2 网页 `/` 布局（产品态）

**首屏（一屏内，手机竖屏）只保留：**

1. **品牌/产品名**：`GNSS NTP`（或短名）— 英雄级，不是导航小字  
2. **大时间**：本地时（主）+ UTC（次）— JS `paintTime` 外推，`/status` 只校准  
3. **一枚状态徽章**：绿/黄/红 + 一句短文案（上表）  
4. **一行身份**：`IP · SSID · RSSI`  
5. **一个 CTA**：`设置`（登录）

**首屏以下（折叠或次卡，默认收起「工程细节」）：**

- 参考：星数、PPS、频偏、Root 质量、residual  
- 服务：served / clients / RATE / DENY（可选迷你计数）  
- 系统：固件标记、uptime、heap  

原则：**调试字段不进第一视口**（对齐 Meinberg「磁贴概览 → 点进 State 细节」）。

### 3.3 OLED（保持，小幅对齐）

维持现 Scheme A：大字时间 + 顶栏星数/态 + 网图标。可选增强：

- 授时中：时间旁或底栏明确 `S1` / `HLD` / `WAIT`（与三色表一致）  
- 不把网页工程字段搬上 128×64  

### 3.4 刷新与传输（结合前序 PPS 推送讨论）

| 通道 | 策略 |
|------|------|
| 网页秒显示 | **本地外推**（已有）+ `utcFracMs` 校准；**不**做 PPS 推全量 JSON |
| 网页其它字段 | 2–5 s 拉一次瘦 `/status` 或现有 `/status`；徽章/星数/频偏不要求 1 Hz |
| 长测/图表 | `/metrics` + 外部 Grafana（LeoNTP 社区同款路径） |
| PPS 推送 | **不做网页默认路径**；若未来要给脚本，单独 UDP/SSE 瘦快照（见前序可行性结论） |

## 4. 分阶段落地（实施时按此序）

### P0 — 信息架构（纯前端 HTML/JS）——**已合入 v1.1.17**

- `/` 改为：大时间 + 三色徽章 + 身份行；原四卡片细节收入 `<details>` 或「高级」折叠  
- 文案中文化统一；去掉首屏 Residual/LI/RefID 等  
- 保持 `/status` `/metrics` 不变（调试与监控入口放页脚）

### P1 — API 可选瘦身——**已合入 v1.1.19**

- `GET /status?view=ui`：徽章字段 + `utcEpoch/utcFracMs` + 身份 + 少量参考  
- 全量 `/status` 留给工具；首页默认拉瘦包，展开「工程细节」时拉全量  

### P2 — OLED/灯语文案对齐——**已合入 v1.1.19**

- Home 底栏与网页徽章同一套 **S1 / HLD / WAIT** 词表  
- README 状态灯表与网页色语义一致（绿=S1 · 黄=HLD · 红=WAIT）

### 明确不做（本方案）

- Meinberg 级多磁贴动态图、PTP、多参考源矩阵  
- 网页 WebSocket/SSE 按 PPS 推送全量状态（成本/收益不符本机定位）  
- 把 Prometheus 图表嵌进设备页面（堆与 flash 不划算）

## 5. 验收标准（P0）

1. 手机打开 `/`：不滚动即可判断「能否当 Stratum-1 用」+ 读到正确本地时。  
2. 弱 WiFi 下秒位连续（外推），偶发 `/status` 慢不导致回跳（v1.1.16 已具备基础）。  
3. 工程师仍能从页脚进 `/status`、`/metrics` 看全量。  
4. OLED/灯语扫一眼结论与网页徽章一致。

## 6. 一句话

正式产品用 **「健康色 + 大时间 + 身份」做首屏**，细节后置；本项目应把网页从「调试 KV 表」收成 **LeoNTP 式主屏 + Meinberg 三色语义**，秒显示继续本地外推，监控走 `/metrics`——而不是继续加轮询频率或上 PPS 推送。
