# S3 特性深挖路线图（PPS 硬件捕获 / PSRAM 历史 / OTA / 外部时钟）

> 状态：立项排序已定（2026-09-18 用户定序：**① RMT 捕获 → ③ PSRAM 历史 → ② OTA → ④ 外部时钟最后**）
> 背景：S3 移植转正后的特性深挖规划，基于 2026-09-18 代码/特性审查；各项目启动前按本档「验收准则」细化
> 相关：[esp32s3_devkitc1_hw.md](esp32s3_devkitc1_hw.md)、[esp32s3_flash_test_20260917.md](esp32s3_flash_test_20260917.md)、[s3_clock_drift_20260917.md](s3_clock_drift_20260917.md)

## 0. 现状基线

| S3 特性 | 现状 |
|---|---|
| 双核 LX7 @240MHz | ✅ task-time 独占 core 1（移植核心收益） |
| 16MB QIO flash | ✅ default_16MB 分区；app1/OTA 槽位**闲置** |
| 8MB OPI PSRAM | ⬜ 仅编译开关，**零使用** |
| 新版温度传感器 | ✅ `temperatureRead()`（tcmp 显示/日志） |
| RMT 4TX | 1 路用于 RGB 状态灯；**RX 4 路全闲置** |
| 3× UART | 2 路在用（调试/GNSS），第 3 路闲置 |
| USB-OTG | 刻意不用（CDC_ON_BOOT=0，走 UART 座） |

## 1. 项目一：RMT RX 硬件捕获 PPS 边沿（第 1 位）

- **现状**：PPS 走 GPIO ISR + `esp_timer_get_time()`——µs 级 ISR 延迟抖动进入相位估计。
- **方案**：RMT RX 通道监听 PPS 引脚，**硬件时间戳边沿**（tick 12.5 ns，零 ISR 延迟），ISR 只做取数通知；与现行 GPIO ISR 路径并存（编译/运行时可选），异常回退旧路径。
- **价值（诚实评估）**：NTP 对外可见收益 ≈ 0——比对 stdev 由网络路径主导（4.34 ms），设备侧抖动本为 µs 级；但相位估计质量上限提高、毛刺甄别（脉宽信息）更可靠（18:43 型双边沿毛刺可直接按脉宽过滤），架构更漂亮。
- **验收**：双路径并存开关 + 24h 对照（residual/qualityMs 分布不劣化）；毛刺样本脉宽记录进 `/status` 调试字段。
- **工作量**：纯软件，估 1 个会话（RMT RX 配置 + 与 ISR 队列对接 + 回退开关）。

## 2. 项目二：PSRAM 诊断环形缓冲 + `/history`（第 2 位）

- **现状**：8MB PSRAM 零使用；长测依赖外部脚本（手机 1 Hz 拉取）。
- **方案**：PSRAM 里放 24h×1 Hz 环形缓冲（freqPpm/tempC/tempRefC/state/residual/quality/sat/rssi），Web 加只读 `/history`（JSON 概要 + CSV 下载）；掉电丢失可接受（RAM 环形），关键事件另存 NVS 计数。
- **价值**：设备自录长测/故障回溯，不依赖外网脚本；`/metrics` 可加直方图（如 qualityMs 分布）。
- **验收**：S3 连续 24h 自录 + `/history` 取回与 `clock_drift_monitor` 并跑数据一致；C3 不受影响（PSRAM 不存在时功能自动关闭）。
- **工作量**：纯软件，估 1–2 个会话（缓冲结构 + web 端点 + C3 禁用路径）。

## 3. 项目三：OTA 双分区升级（第 3 位）

- **现状**：app1 槽位（6.25MB）闲置；升级必须拆机接串口。
- **方案**：`/cfg` 加固件上传（登录会话内）→ 写 app1 → `esp_ota_set_boot_partition` → 重启切换；保留串口升级为兜底；上传失败/校验失败自动回滚（rollback 机制）。
- **价值**：产品化远程升级，运维体验质变。
- **验收**：S3/C3 各完成一次 Web OTA 往返（新→旧→新），断电/坏包场景回滚验证；NVS 配置跨升级保留。
- **工作量**：纯软件但安全敏感（会话/校验/回滚），估 2 个会话。
- **注意**：C3 的 4MB default.csv 双 app 槽各 ~1.2MB，当前固件 ~934KB 可用但余量小——C3 端 OTA 需评估或换分区表（动 NVS 布局需谨慎，涉及已部署设备）。

## 4. 项目四：外部高品质时钟源（最后，硬件依赖）

- **现状**：Holdover 真实上限 = 板载晶振（S3 −12.3 ppm / C3 −1~−2.7 ppm），5 分钟级守时已到顶。
- **候选路径**（启动前调研定案）：
  a. I2C 接 **DS3231 类 TCXO RTC**（±2 ppm）作 Holdover 参考钟——改动最小；
  b. 外部 **OCXO/原子模组** 供电驯服——精度质变但电源/空间成本高；
  c. **第二 PPS 输入**（外部源）作交叉校验。
- **价值**：守时从「分钟级」到「小时级」——唯一能改变产品精度等级的方向。
- **前置**：购件 + 接线 + `config.h` 抽象第二时钟源接口；建议在 ①③ 落地后启动。
- **验收**：拔 GNSS 电源 NTP offset 漂移 ≤ 目标值（按选定钟型定，DS3231 约 ±2ppm×300s≈0.6 ms）；24h 频偏曲线对比板载晶振。

## 5. 明确不做

- **NTS/加密 NTP**：有 AES/SHA 加速器也不做——局域网场景，阶段 C 界定不变
- **IDF5 / Arduino 3.x 迁移**：迁移成本 >> 收益，当前 2.0.17/IDF4.4 稳定运行
- **触摸 / LCD 外设 / 802.11mc**：与产品无关

## 6. 排序备忘

**① RMT 捕获（纯软件、技术迭代）→ ③ PSRAM 历史（纯软件、运维价值）→ ② OTA（纯软件、产品功能、安全敏感放后做稳）→ ④ 外部时钟（硬件项目、收益最大、最后启动）**
