# IDF5 / Arduino 3 适配说明（v1.1.24）

> 分支：`cursor/idf5-adapt-a05e`  
> 平台：pioarduino **55.03.311** = Arduino-ESP32 **3.3.11** / ESP-IDF **5.5.5**  
> 基线：main `4674d5b`（v1.1.20）上的 GNSS NTP 固件

## 为何换平台

库存 PlatformIO `espressif32` 6.x/7.x 仍绑 Arduino 2.x / IDF 4.4。S3 上 legacy RMT RX 数据通路只会推送空环形缓冲项（见 `docs/s3_deep_dive_roadmap.md` §1），必须迁到 IDF5 新 `driver/rmt_rx.h` 才能重开 PPS 硬件捕获。

## `platformio.ini`

```ini
platform = https://github.com/pioarduino/platform-espressif32/releases/download/55.03.311/platform-espressif32.zip
```

C3 / S3 共用该 pin；板级差异仍在 `include/config.h`。

## 代码改动摘要

| 区域 | 变化 |
|---|---|
| 温度 | C3 去掉已删除的 `driver/temp_sensor.h`，与 S3 一样走 `temperatureRead()` |
| RMT | 删除 IDF4 `driver/rmt.h` / `rmtInit`/`rmtRead` / `rmt_config` 双路径；改为 `rmt_new_rx_channel` + `rmt_receive` + `on_recv_done` → 队列 → `rmtRxTask` |
| 默认 | `GPS_PPS_RMT_EN=0`（GPIO ISR 生产路径不变）；置 1 即启用 IDF5 RMT 实验 |
| S3 DMA | 优先 `with_dma=1`，失败回退非 DMA；C3 固定非 DMA |
| RGB 灯 | `neopixelWrite` → `rgbLedWrite`（Arduino 3 弃用 API） |

## 模块兼容性审核（相对 Arduino 3.3.11 / IDF 5.5.5）

对 `src/` / `include/` 全量对照框架头文件与编译告警；结论：**除已改的 GPS 温度/RMT/RGB 外，其余模块 API 仍有效，无需结构性改写**。

| 模块 | 关键依赖 | 审核结果 |
|---|---|---|
| `wifi_manager` | `WiFi.onEvent` / `ARDUINO_EVENT_*` / `scanNetworks` / SoftAP / `setScanMethod` | ✅ 事件名与 `WiFiEventInfo_t`（`got_ip` / `wifi_sta_disconnected`）布局与 Arduino 3 Network 层一致；`WIFI_ALL_CHANNEL_SCAN` 仍在 IDF 头中 |
| `ntp_server` | `WiFiUDP` | ✅ `WiFiUdp.h` 仍提供；`begin`/`parsePacket` 签名未变 |
| `web_portal` | `WebServer` / `HTTPUpload` / ArduinoJson 7 | ✅ 同步 WebServer 仍在核心库；`JsonDocument` API 兼容 |
| `ota_service` / `app_ipc` | `Update` / `esp_ota_*` / `esp_image_verify` / `ESP_CHIP_ID_*` | ✅ chip_id 枚举值未变（C3=`0x0005`，S3=`0x0009`）；`Update.isRunning/errorString` 仍在 |
| `main` TWDT | `esp_task_wdt_add/reset` | ✅ Arduino 核心仍初始化 TWDT；`add(nullptr)`=当前任务，用法合法 |
| `settings` | `Preferences` / `esp_crc32_le` | ✅ Preferences API 未变；`esp_crc.h` 可解析 |
| `display_ui` / `ext_clock` | `Wire` / Adafruit SH110X | ✅ `Wire.begin(SDA,SCL)` / `display.begin(addr)` 正常链接 |
| `encoder` / PPS GPIO | `attachInterrupt` / `esp_timer_get_time` | ✅ ISR 路径无框架变更 |
| `local_clock` | `esp_timer` | ✅ 无变更 |
| `status_leds` | RGB RMT TX | ✅ 已迁 `rgbLedWrite`；与 PPS RMT RX 分通道池，默认 EN=0 无冲突 |

### 容量注意（C3）

IDF5 镜像明显变大：app ≈ **1.15 MB / 1.31 MB**（`default.csv` ota 槽 `0x140000`，约 **87%**）。OTA 双槽仍放得下，但后续加功能前需盯 C3 余量（S3 16 MB 分区充足）。

### 编译验收

```text
pio run -e esp32-c3 / esp32-s3   EN=0 → SUCCESS（无弃用告警）
临时 GPS_PPS_RMT_EN=1           C3/S3 → SUCCESS
```

## 板测建议

1. 先以 `EN=0` 刷机，确认 GNSS 锁定 / NTP / Web / SoftAP / OTA 与 v1.1.20 行为一致。  
2. 再开 `EN=1`，看串口 `[pps-rmt] idf5 armed ...` 与 `/status` 的 `ppsRmt.*`（`idfDataFrames` 应随 PPS 增长）。  
3. 对比 `ppsRmt.deltaMeanUx10`（RMT−GPIO）；异常则保持 `EN=0` 并记档。

## 已知注意

- 需 PlatformIO Core **≥ 6.1.19**（本环境用 6.2.0）。  
- S3 RGB（`rgbLedWrite`）占 RMT TX；PPS RX 由驱动从池中分配。  
- 未合入的旁支（PCAS persist / 寄存器 RMT）与本迁移独立，可随后 rebase。
