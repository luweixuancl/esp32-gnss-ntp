# piod — pio 构建守护/包装器设计（2026-09-16）

> **历史归档**：下文口径以当时固件为准。当前 `main` = **v1.1.39** / IDF5，见 [CURRENT.md](CURRENT.md)。


## 背景

2026-09-16 另一 opencode 控制台死机：`pio run` 末尾 SCons `SConsign.write()` 在 tmpfs 上抛一次性
`Errno 38 ENOSYS`（见 AGENTS.md 构装备忘），崩溃后 pio 在解释器收尾阶段 100% CPU 空转不退出，
发起构建的 opencode bash 工具调用死等，整个 TUI 冻结（孤儿进程烧了 11 分钟 CPU 后手工 kill）。

## 目标

opencode 控制台发起构建**永不死等**：启动即返回；构建在后台跑，受硬超时保护；
进度/结果可随时查询；两控制台不能并发构建同一 workspace。

## 形态

`/root/bin/piod` 单文件 bash（sdcard FAT 无 exec 权限 → 装 f2fs；依赖 bash/setsid/flock/timeout 均已在）。
状态目录 `/tmp/opencode/piod/`（tmpfs，重启自清）：`lock` `pid` `rc` `log`。

## 接口

| 命令 | 行为 |
|------|------|
| `piod start [pio 参数…]` | 后台启动 `pio run`，**立即返回**；已有构建则拒绝 |
| `piod status` | RUNNING（PID/时长/日志尾 5 行）或 FINISHED（rc 判定）或 IDLE |
| `piod log [N]` | 日志尾 N 行（默认 30） |
| `piod wait [秒=600]` | 有界等待：构建完→打印 rc+日志尾并 exit rc；超时→exit 124 不杀构建 |
| `piod stop` | TERM 进程组 → 最多等 10s → KILL |

## 机制

- `start`：`flock -n` 抢 `lock`（fd 9 由后台子进程继承持有，构建期间天然互斥）→ 清空 log/rc/pid →
  `setsid` 派生自身 `__child` 分支（新会话，进程组 = pid，便于组杀）→ 写 pid 文件。
- `__child`：cd 项目目录 → `PLATFORMIO_WORKSPACE_DIR=/tmp/opencode/pio-ws` →
  `timeout -k 10 540 pio run >log 2>&1` → `echo $? > rc` → 删 pid。
- **防死等根**：即使复现 ENOSYS 空转，`timeout -k` 540s 必杀（rc=124 标记「疑似挂死被终止」），
  孤儿最多存活 9 分钟；opencode 侧 `start` 秒回，`wait` 也有界。
- 固定常量：项目 `/root/程序/esp32c3-gnss-ntp`，workspace `/tmp/opencode/pio-ws`；参数透传（如 `-t upload`）。
- 交互式 `pio device monitor` 不适用（设计目标是非交互构建/上传）。

## 验收（2026-09-16 实测）

1. `piod start` → 秒回，status 显示 RUNNING；构建中二次 `start` 被拒（exit 1）。
2. `piod wait 600` → rc=0，日志尾 `SUCCESS`（增量 71s 级）。
3. `piod stop` → 组杀生效，无残留进程；随后 `start` 可正常再启动。
4. `piod wait` 在无构建时立即返回（IDLE/上次结果）。
